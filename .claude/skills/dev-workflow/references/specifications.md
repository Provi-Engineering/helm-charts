# Accepted design

A ticket-keyed specification (one named for its ticket key) merged to `main` is accepted design
(the ticket carries the intent): read it wherever the work needs it, and never treat it as
evidence of how the code works, since its status text may be stale. A specification without a
ticket key is not accepted design: do not plan from it or rate a ticket against it. The intent
review's `pickup` trigger re-validates a specification before work resumes from it.

The specifications rule and the `CLAUDE.md` in the specifications directory hold the rest: when a
specification is written, its form, and how edits to it are made.
